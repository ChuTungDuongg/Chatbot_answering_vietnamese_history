# Central V2: multi-entity biography and relationship regression

This implements the additional attached request after the frontend layout task. The frontend fix is reported separately in `frontend/CHAT_LAYOUT_REGRESSION.md`; its changes do not alter backend behavior. This explicitly requested follow-up does change Central's relation-question handling. API schemas, public modes, model loading and state-machine phases remain unchanged.

1. **Why Nguyễn Văn Thiệu was retrieved and discarded.** The biography extractor returned only the first subject. The normal single-person filter then reserved exact-title evidence for Võ Nguyên Giáp and could reject other titles once enough exact hits existed. The biography sufficiency branch only required evidence for that primary subject. Together, these rules erased the second requested person while still declaring the whole question sufficiently grounded. Single-person filtering remains intact; the relation-specific branch bypasses that inappropriate one-person collision rule.

2. **Parser changes.** `CentralQuestionAnalysis` retains `question_type=biography` and adds `related_entities`, `relation_requested` and `relation_phrase`, with `identity` and `relationship` facets. A bounded deterministic Vietnamese grammar recognizes the supplied identity-plus-relation, relationship-with, relationship-between, related-to-each-other, meeting/working/opposition and role-toward forms. Names are extracted from the request; no Võ Nguyên Giáp/Nguyễn Văn Thiệu fact or name pair is hardcoded. The current bounded grammar handles a primary person and one related person, rather than inventing an open-ended entity parser. Existing single-person, cause and comparison parsing remains.

3. **Retrieval and provenance.** Relation questions run three independent local queries: primary identity, related identity and co-occurrence. Query text contains the requested names without historical conclusions. Evidence gets recomputed `covered_entities`, `canonical_entities`, `entity_roles` and `direct_relation_spans`; the retrieval origin also records its entity role. Default four-source selection reserves each person's usable identity evidence, then a direct-relation source when available, and fills remaining slots with canonical sources before peripheral anecdotes. This keeps strong Nguyễn Văn Thiệu chunks ahead of the observed side-topic pages. Excerpting and total budgets remain active. When direct evidence is still missing and Wikipedia tools are enabled, one deterministic co-occurrence search is followed by at most three unique canonical/direct-result page fetches. Search snippets guide fetches and never establish sufficiency. No extra LLM action is used to decide the fallback, and the local co-occurrence query is not repeated.

4. **Separate coverage and validation.** Before synthesis, require usable selected evidence for both names. Report `relationship_balance`, `primary_subject_evidence_count`, `related_entity_evidence_count` and `direct_relation_evidence_count`. A direct-relation span must connect the two names through a concrete interaction/relationship predicate in the same clause. Merely sharing a source, a sentence about a third person, or a search result does not prove interaction. A question with only primary-person evidence stays insufficient and does not enter a speculative model action. Answer validation separately rejects documented-predicate mismatches, unsupported direct meetings, command relationships, personal rivalry and unsourced explicit opposing-side context. These deterministic checks are conservative and cover explicit lexical relationship forms; they do not claim exhaustive semantic entailment for every paraphrase.

5. **Partial-answer policy.** Both identities can be sufficiently supported while the direct relationship remains unresolved. In that case, report `partial_answer=true`, `unresolved_facets=["relationship"]`, and instruct synthesis to answer the supported portion and state the evidence limit. The standard caveat is: “Bằng chứng hiện có chưa xác lập một mối quan hệ trực tiếp cụ thể giữa hai người.” If the answer merely omits the caveat, the host appends that truthful packet-coverage statement without another generation, then validates the answer normally. This cannot rescue an invented meeting or other unsupported claim. An evidence limit is not a claim that the two people never interacted. Broader historical opposition may be described only when supplied context supports it. No historical relationship is hardcoded.

6. **History relevance.** Explicitly named, independently parsed subject/event/comparison questions normally send zero history messages. Questions with unresolved references such as “ông ấy”, “người này”, “sự kiện đó” or “chức vụ đó”, and ambiguous follow-ups, keep the existing bounded context. Telemetry records `history_relevance_mode`, `history_turns_considered`, `history_turns_selected`, plus the existing input character/message counts. The production-like relation question after eight unrelated user/assistant messages selects zero; the follow-up “Ông ấy giữ chức vụ đó đến năm nào?” retains the necessary preceding entity context. This adds a conservative relevance gate rather than an LLM context resolver.

7. **Hồ Chí Minh name diagnosis and alias support.** The supplied regression text does not include the full selected excerpts and rejected answers, so it cannot establish whether the production answer unnecessarily added Hồ Chí Minh or relied on an alias missing from the packet. The old guard checked literal names in the question and selected text/title. If Hồ Chí Minh appears there, it is already supported; Nguyễn Ái Quốc alone cannot establish the alternate name without additional evidence. The new internal evidence packet can carry aliases explicitly stated in selected text or selected `metadata.entity_aliases` mapping a visible entity name to aliases. Such metadata is accepted only when its named anchor exists in the selected body/title, and aliases are shown to synthesis. Text-derived aliases disappear if excerpting removes their equivalence. No manual historical alias database or Hồ Chí Minh whitelist is added. `entity_alias_matches` identifies the actual selected source and origin. Tests show Nguyễn Ái Quốc alone still cannot authorize Hồ Chí Minh, explicit equivalence can, and unrelated/stale alias metadata cannot.

8. **Repair behavior.** Unsupported names are supplied explicitly in the existing one-shot repair prompt, with an instruction to remove them and optional associated claims entirely unless supported by the packet, without replacing them with another unsupported claim. All answer-derived validators are recomputed from the repaired answer. A fake repaired answer removing Hồ Chí Minh passes; repeating the unsupported name still fails closed. The optional arbitrary-sentence deletion path was not added: determining that a historical sentence is nonessential is not reliable from a name hit alone. A bounded full repair remains the conservative fallback. Adding a known evidence-limit caveat is safe because it makes no historical assertion beyond the selected packet's coverage.

9. **Model calls and latency.** Both documented-relation and relation-absent fixtures pass with **one synthesis**, no action generation and no full repair. The latter returns a supported partial answer with a caveat. Full repair remains exceptional for real unsupported claims. The supplied production trace spent approximately 17.1 seconds on its second generation; avoiding that stage is the intended saving. Relation queries now seek both people and their connection, so they intentionally perform more targeted retrieval than the erroneous one-person path. No live GPU timing or exact speedup is asserted. Existing CMT8 one-query skipping, safe cold-load overlap, evidence compaction, source display, comparison balance and viewpoint span checks remain covered by regression tests.

10. **Files and verification.** New modules: `app/agents/central_relationships.py` and `central_entity_aliases.py`. Updated: `central_question.py`, `central_analytical.py`, `central_evidence.py`, `central_compaction.py`, `central_grounding.py`, `central_agent.py`. New tests: `tests/test_central_relationships.py`. The internal evidence-field assertion in `tests/test_central_quality_hardening.py` now includes aliases. An existing concurrency test in `tests/test_central_agent.py` used a brittle total-wall-time threshold; it now proves simultaneous tool entry with a bounded barrier instead. The focused Central run passes **216 tests in 25.33 seconds**, including 30 new relation cases and existing biography, Bạch Đằng, Nhà Trần, US/VNCH, CMT8, comparison, citation, viewpoint and latency tests. Full-suite/static results are recorded below after completion.

Full verification: `python -m pytest -q` passed **780 tests, with 1 skip, in 59.57 seconds**. The skip is the absent legacy V1 Colab notebook. Tests ran with Hugging Face/Transformers offline and CUDA visibility disabled. `python -m compileall -q app tests/test_central_relationships.py` and `git diff --check` passed. Frontend results are reported separately: 14 unit tests, 18 browser tests, build and lint passed.

Additional telemetry is emitted through the existing Central debug/provenance/performance dictionaries, with no API schema change. No new model, Qwen weights, GPU inference, training, Modal command, deployment or volume mutation was used.
