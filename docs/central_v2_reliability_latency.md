# Central V2 reliability and latency pass

Scope: current repository state, with the earlier retrieval, comparison, viewpoint and frontend work preserved. Verification uses local CPU tensors, fake models and fake timing only. The production trace below was supplied by the user; it was not independently reproduced against Qwen or Modal.

1. **Why the first CMT8 request failed.** The supplied first synthesis had `missing_valid_citations` and `uncited_factual_paragraphs`. The old path invoked a full answer repair; it still failed those checks. A shared fail-closed fallback then described this answer-validation failure as insufficient evidence. The trace establishes this control-flow failure, but cannot establish why the base model omitted citations or whether cold initialization caused that omission. A repeated question in an altered conversation was not a controlled warm/cold comparison.

2. **Why this was not a model-load failure.** The trace reports `central_model_ready=true`, `central_model_load_error=null`, `central_adapter_loaded=false`, and `evidence_sufficient=true` with `causal_target_and_dimension_coverage`. Both synthesis and repair executed after successful initialization. The approximately 23,819 ms model load was a latency cost, not the reported answer failure.

3. **Previous ordering.** `CentralAgent.run()` awaited readiness before `_run()` performed deterministic initial grounding. Analytical query variants were submitted eagerly. The request therefore paid model load, retrieval, synthesis and potentially a full rewrite sequentially. Existing `LazyRuntime` already cached its initialized runtime behind a double-checked lock.

4. **New ordering.** PREPARE → INITIAL_GROUNDING → optional ACTION/TOOL_EXECUTION → SYNTHESIS → bounded citation/quality recovery → FINAL remains the same Central pipeline. On a safe cold request, the existing single-flight initialization starts beside initial grounding; an explicit readiness barrier precedes any model action or synthesis. On unsafe retrieval, readiness precedes retrieval. Warm requests skip initialization entirely. Load waiting is excluded from the ordinary agent budget; each generation also enforces the same remaining deadline for cold and warm requests.

5. **Overlap safety and deployment limitation.** `SearchHistoryTool.can_overlap_model_load_and_retrieval()` reads the already-loaded embedder and reranker devices without creating another runtime. Both must report CPU; mixed, CUDA and unknown placement remain sequential. The configuration switch can disable overlap but cannot override this safety check. The current `RAGService` creates both SentenceTransformer and CrossEncoder on `settings.device`, and the deployed configuration uses CUDA. Therefore the current same-CUDA deployment receives **no load/retrieval overlap saving**. This pass intentionally does not relocate retrieval models or overlap unproven GPU work. `LazyRuntime` is reused unchanged, with no second initializer or synthesis before readiness. A timed-out native loading thread cannot be forcibly stopped; its existing lock still prevents duplicate initialization.

6. **Model loading and attention.** Preserve default `Qwen/Qwen3-8B`, bfloat16, direct CUDA placement `{"": 0}`, `eval()`, local cache behavior, and the optional validated future V2 adapter. Explicitly request `low_cpu_mem_usage=True` and safetensors. No offload, compilation or old adapter is introduced. Local inspection found PyTorch 2.13.0, Transformers 4.57.6 and safetensors 0.8.0; flash-attn was absent. Qwen3's installed implementation supports SDPA and FlashAttention. Selection uses existing compatible CUDA FlashAttention2 when available, otherwise supported SDPA, otherwise eager attention; expose `attention_backend`. No dependency was installed. Existing deployment requirements already include accelerate, although it is absent from the local audit environment. Actual deserialization/transfer savings require an authorized GPU measurement later.

7. **Generation and warm fast path.** Add `torch.inference_mode()` and explicitly disable scores, hidden states, attentions and generation dictionaries. Preserve deterministic decoding, `use_cache=True`, `enable_thinking=False`, and model `eval()`. Cache tool schemas by the allowed-tool set; tokenizer, model, generation configuration and runtime remain cached. Warm requests do not resolve files, scan adapters or reconstruct the model. Existing Qwen/Hermes tool calling remains intact. Readiness and generation have separate bounded failure paths.

8. **Adaptive retrieval.** Run the canonical facet-aware query first. Skip a secondary variant only after checking distinct strong evidence, an overview anchor, requested dimensions and coverage. Causal plans require at least three distinct strong chunks before skipping. A weak primary still executes the secondary. Comparison runs each target's primary independently and evaluates secondary queries within that target's plan; evidence for A never removes the requirement to retrieve B. Existing target provenance, balancing and deterministic fallback remain. Record planned/executed/skipped query lists and skip reasons.

9. **Incidental pages.** Extend event disambiguation with `event_incidental_artifact` for clear song/composition, street, square, monument, station, district and commemoration collisions based on page title, lead and metadata. Existing calendar, place, wrong-event and foreign-scope checks remain. The CMT8 fixture retains three canonical event chunks and rejects the calendar month, Xuân Oanh song, street, square and unrelated 1975 event. An explicit question about the song remains valid.

10. **Evidence and history compaction.** Select coverage before trimming and prefer strong complementary sources over weak quota fillers. Default excerpt budget is 1,600 characters per source, subject to the existing total packet cap. Rank complete sentence units by query/facet relevance; retain at most two windows with surrounding context. Keep quotation/reporting boundaries together and recompute viewpoint annotations and comparison origins from the exact visible excerpt. An indivisible over-budget sentence/quote is omitted rather than cut into misleading text; sufficiency can then fail closed. Titles and aliases remain. History defaults to four messages and 2,400 characters, excludes trace/source fields and duplicate prior attempts, and retains real follow-up context. Character counts and approximate token counts (characters divided by three, not tokenizer measurements) make compaction observable. The synthesis contract now explicitly requires supplied `[S#]` aliases at the end of each factual paragraph, multiple aliases when appropriate, and host-side display conversion.

11. **Citation normalization.** Before validation, normalize unambiguous grouped and adjacent aliases, including `[S1, S2]`, `[S1,S2]` and `[S1][S2]`. Unknown aliases remain errors. Bracketed dates such as `[938]` and `[1945]` are not guessed as citations. Public display remains numeric `[1]`, `[2]`, with existing source IDs preserved.

12. **Conservative host alignment.** Attempt alignment only when remaining issues are missing citations/uncited factual paragraphs. The existing CrossEncoder is loaded, but exposes raw retrieval-ranking scores with no calibrated paragraph-entailment threshold; calling it on same-CUDA retrieval would also serialize GPU work. This pass uses the permitted deterministic alternative: normalized words, distinctive trigrams, named/year grounding checks, all numeric claims, negation and target provenance. Each clause must meet the configurable 0.88 support threshold; the 0.08 margin rejects a close below-threshold competitor. Independently high-support sources are valid alternatives. No rank-based first-source assignment or blanket citation insertion is allowed. Tables abstain because row-wide insertion could conceal a cell mismatch. Revalidate the full answer after insertion; success returns immediately with one model call and `repair_used=false`. This scorer measures conservative lexical support, not general semantic entailment; it intentionally abstains on many paraphrases.

13. **Tiny citation repair.** If alignment leaves only citation problems, run a tool-free `CITATION_REPAIR` substage with a default 128 new tokens. Input contains paragraph IDs/text and compact evidence aliases, titles, excerpts and target provenance. Output must be a strict JSON paragraph-to-alias mapping (an exact JSON code fence is accepted). Duplicate keys, unknown IDs/aliases and malformed values are rejected. The mapping is a proposal: host checks the same support threshold before inserting citations and runs all ordinary validators again. It cannot rewrite history or confer support on a low-confidence match. Tiny repair can resolve a proposal among ambiguous candidates; it is not a general paraphrase recovery model.

14. **Full repair policy.** Retain the existing bounded full quality repair for unsupported claims/years, viewpoint attribution, wrong comparison targets, missing comparison content and other substantive failures. Pure citation failures use normalization → alignment → tiny mapping and then a controlled validation failure by default. `CENTRAL_CITATION_FULL_REWRITE_FALLBACK=true` explicitly opts into one full rewrite after citation recovery fails. The default is false. `repair_used` retains its full-repair meaning; separate flags account for mapping and alignment.

15. **Final failure semantics and progress.** `final_failure_reason` distinguishes `evidence_insufficient`, `answer_validation_failed`, `generation_timeout`, `model_load_failed` and `tool_failed`. Genuine evidence failure retains the existing `insufficient_evidence` public status/copy. Evidence-sufficient validation failure instead says: “Đã tìm thấy tư liệu phù hợp, nhưng câu trả lời chưa vượt qua bước kiểm tra chất lượng và trích dẫn. Bạn có thể thử lại.” Rejected answers expose no accepted citation IDs. Existing SSE progress reads actual loading/retrieval/answering stage state instead of advancing Central phases on a timer. The frontend shows “Đang khởi động mô hình...”, “Đang tìm tư liệu...” and “Đang tổng hợp câu trả lời...”, plus a distinct validation-failure panel. Polling remains at the existing interval, so short stages may not be displayed. There is no new endpoint, page-open warmup or frontend redesign in this pass.

16. **First-turn regression.** Empty-history CMT8 tests use sufficient canonical evidence and an otherwise valid first synthesis with missing citations. Cold safe and unsafe requests recover host-side, return `ok`, use one model generation and one primary retrieval, and report zero history messages. Correctness does not require a previous failed assistant answer.

17. **Cold/warm parity.** The same evidence and fake output produce identical accepted answers and quality results with cold and ready runtimes. The factory runs once across the two requests; the warm wait is zero. Additional cold/warm timeout tests exhaust the deadline only after grounding and both return `generation_timeout` with evidence sufficiency retained. Tests prove scheduling and policy parity; they do not assert bitwise output equivalence from live GPU kernels.

18. **Latency evidence and expectations.** A local illustrative fake run with 200 ms load and 80 ms retrieval completed in 313.9 ms sequentially versus 220.0 ms with safe overlap, including host processing. Recorded retrieval wall times were 94.1/92.9 ms, load waits 203.1/109.9 ms, overlap savings estimates 0/92.9 ms, and alignment 5.9/4.8 ms. Both returned `ok` with one model call. Tests assert event ordering rather than brittle wall-time cutoffs. Safe overlap can save at most the shorter load/retrieval duration; same-CUDA placement saves zero from overlap. Adaptive skipping removes one redundant search in the adequate CMT8 fixture. Smaller packets/history reduce expected prefill work, with no asserted GPU speedup. Host recovery removes the second full generation: the supplied trace's roughly 14,235 ms repair is the relevant avoidable stage, not a measured saving from this implementation. A 128-token mapping still pays prompt prefill and is not guaranteed to run in a fixed fraction of that time. The approximately 24-second cold model load remains a real cost requiring later measurement. Keep `min_containers=0`; idle retention remains 120 seconds by default. `CENTRAL_SCALEDOWN_WINDOW_SECONDS=300` is an optional deployment-time cost/latency tradeoff, not enabled here.
